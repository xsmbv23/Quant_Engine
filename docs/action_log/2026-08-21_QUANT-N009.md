## N009 work

Created:

- `contracts/parser_xsmb_v1.json`
- `tools/verify_parser_contracts.py`
- `tests/test_parser_contracts.py`

The contracts establish the semantic parser boundary:

1. Input is exact captured response bytes + immutable raw receipt.
2. Raw SHA-256 must match the upstream receipt.
3. Source identity and runtime identity are mandatory.
4. Official result panel is the only truth-bearing page region.
5. Ads, navigation, header/footer chrome, generic page numbers and unrelated tables are non-truth content.
6. Ambiguous panels deny.
7. Canonical domain is exactly XSMB 27 positions, each integer 0..99.
8. Missing/duplicate/unmapped truth positions deny.
9. Semantic SHA-256 is computed only over the canonical 27-value domain.
10. Parser failure emits compact receipt only; raw artifact is immutable.
11. Promotion is forbidden in Room 01.

## Additional forensic challenge

The existing `.github/workflows/admission_check.yml` creates a JSON file with `status=PASS` and `evidence_score=1`, then uploads it. That is a workflow-generated assertion, not proof that the runtime, parser contracts, or external service actually passed.

This does not alter Brain authority, but it is a potential evidence-semantics hazard for future Bots.

Rule added to this log:

`WORKFLOW_SELF_ASSERTION != INDEPENDENT_RUNTIME_EVIDENCE`

The workflow should be hardened to execute real repository verifiers/tests and label its artifact as workflow execution evidence, not as proof of external runtime truth.
