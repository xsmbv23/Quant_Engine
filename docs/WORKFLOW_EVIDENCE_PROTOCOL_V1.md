# Workflow Evidence Protocol V1

## Purpose

This protocol hardens the Quant Engine execution/evidence boundary without changing the frozen Brain foundation and without granting promotion authority to Layer 1.

## Authority separation

```text
Project_Brain_AI
    = Governance / Forensic FSM / persistent authority

Quant_Engine
    = Layer 1 research and execution plane

Chat
    = communication interface only
```

Quant Engine may produce evidence. It may not reinterpret, reopen, or promote a Brain gate.

## Evidence classes

### 1. Repository evidence

Evidence that a file, test, workflow definition, or commit exists.

This proves repository state only.

### 2. Workflow execution evidence

Evidence emitted by an actual CI/workflow run for a specific commit SHA.

Required fields:

- repository
- workflow identity
- commit SHA
- run identity
- execution timestamp
- result
- test summary
- artifact/evidence hash when applicable

A repository file that merely describes a workflow is **not** workflow execution evidence.

### 3. Runtime evidence

Evidence emitted by the actual deployed runtime.

Runtime evidence cannot be substituted by CI evidence.

### 4. Research evidence

Evidence generated by a Layer 1 room from canonical real data.

Research evidence must carry:

- source identity
- source/canonical input hash
- room identity and version
- parameter signature
- temporal anchor
- OOS/walk-forward status
- result status

## Promotion rules

```text
REPOSITORY_EVIDENCE
      !=
WORKFLOW_EXECUTION_EVIDENCE
      !=
RUNTIME_EVIDENCE
      !=
RESEARCH_EVIDENCE
```

No evidence class inherits authority from another class.

`PASS` is local and prerequisite-only.

`UNKNOWN` is not PASS.

Missing workflow execution receipt means CI state is `UNKNOWN`, never `PASS`.

## Cross-Bot rule

If another Bot reports that a workflow, deploy, database operation, or research run succeeded, Quant Engine must treat that report as an observation claim until the corresponding machine-verifiable receipt is available.

Do not duplicate work solely to manufacture a matching green status.

## Render safety

Render Free 512 MB remains a hard boundary. Workflow evidence collection must be bounded and must not load historical datasets into the Brain runtime.

## Forensic immutability

Historical evidence is append-only. A corrected result creates a new receipt/version; it does not overwrite the previous evidence.

## Current gate

This protocol does not authorize Layer 1 promotion. Brain remains the sole authority for promotion and corridor admission.
